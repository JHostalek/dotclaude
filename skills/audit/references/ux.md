# UX

- Flag primary tasks that cannot be completed, broken navigation, dead ends, or actions whose required controls are unreachable.
- Flag labels and explanations that expose internal jargon or fail to tell the user what an action does and what information it needs.
- Flag grouping or navigation that makes users understand the storage model instead of finding the concepts relevant to their task.
- Flag confirmations or visible feedback that claim a change succeeded before it persisted, or conceal partial completion.
- Flag unnecessary choices, missing hierarchy, or advanced controls that make a routine task harder to understand.
- Flag errors that erase input, provide no actionable recovery, trap users in progress, or treat a failure as an empty result.
- Flag destructive actions whose confirmation, cancellation, or recovery does not match their actual consequence.
- Flag keyboard traps, unreachable controls, missing focus visibility, inaccessible semantics, or information conveyed only through color.
- Flag loading, first-use, no-results, partial-data, timeout, offline, missing-data, or long-content states that break the supported flow.
- Flag navigation that loses filters, selection, unsaved work, or the user's return location without an intended reason.
- Flag optimistic or real-time state that hides conflicts, stale results, duplicate submissions, or changes to the wrong item.
- Flag layout, text, animation, or controls that fail on supported devices, languages, accessibility requirements, or the established design system.
- Flag long operations without meaningful progress, or performance that blocks the user's task under the supported workload.
- Flag hidden opt-outs, disguised actions, false urgency, or misleading defaults that prevent users from making an informed choice.
